## 第 1 頁：封面

- **阿斯拉量化系統 V2**
- 一句定位：**LLM 驅動的加密貨幣／台股量化分析與決策輔助平台**
- 技術棧：FastAPI · React + TypeScript · SQLite · 多 LLM（OpenAI / Gemini / Claude / Ollama）· LightGBM / 神經網路
- 作者：TonyY ｜ 開發期間：2026/03–2026/06（約 3 個月）

> 講稿：這是我獨立開發的量化分析平台，同時支援加密貨幣與台股。它的特別之處不只是功能多，而是「我如何和 AI 大規模協作、又用一整套工程紀律守住品質」——這會是今天的主軸。

## 第 2 頁：問題與動機

- 量化交易決策的兩難：既要**數據嚴謹**，又想用 **AI 加速分析**
- 但風險是：**盲目相信 AI 的判斷，會傷害一個本來有效的策略（alpha）**
- 我的命題：能不能打造一個系統，讓 **AI 是「被驗證、被約束」的工具，而不是黑箱替代品**？

> 講稿：市面上很多「AI 看盤」工具，問題是你不知道它什麼時候在唬你。我想解決的是——讓 AI 的每個判斷都能被統計驗證、每次改動都被制度約束，這樣 AI 才真的可信。

## 第 3 頁：系統全貌

- 架構：**React 前端 ↔ FastAPI 後端 ↔ SQLite ＋ 多 LLM ＋ ML 推論 ＋ 雙市場資料源**
- 規模感（可查證）：
  - 後端 146 個 Python 檔（約 5.7 萬行）＋前端 21 個 TS/TSX（約 1.7 萬行）≈ **7.5 萬行**
  - 約 **204 個 commit**，3 個月內從 v100 迭代到 v149
- 資料層：7 個 SQLite（predictions / chat_history / analysis_cache / semantic_cache / knowledge…）

> 講稿：整體是前後端分離的架構。三個月做到約 7.5 萬行、200 多個 commit、版本從 v100 推進到 v149，這個迭代速度本身就跟 AI 協作有關，等一下會展開。

*來源：`git rev-list --count HEAD` = 204；`find/wc` 行數統計。*

## 第 4 頁：核心功能總覽

- **LLM 智能分析**：多供應商、即時 streaming、function calling、視覺看圖
- **技術指標**：43 個動態指標（趨勢／動量／波動／量能／支撐壓力）
- **市場狀態（Regime）**：4 主類型 ＋ 5 個 ranging 子類型自動判別
- **SMC 結構偵測**：Order Block / BOS / CHOCH / Fair Value Gap
- **ML 預測**：7 種模型（LightGBM / XGBoost / LSTM / GRU / CNN-LSTM / Transformer…）
- **回測引擎**：CPCV / Walk Forward / Monte Carlo / 參數優化
- **預測追蹤**：結構化預測 → 自動驗證命中率
- **掃描器**：台股 2000+ 檔 ＋ 加密多交易對
- **雙市場**：加密貨幣 ＋ 台股，共用指標引擎

> 講稿：功能涵蓋從「看圖、算指標、判斷市場狀態」到「ML 預測、回測驗證、追蹤準確度」的完整閉環，而且加密和台股共用同一套引擎。

## 第 5 頁：技術亮點① — 多 LLM Adapter 工廠模式

- 用 **工廠模式** 統一 5 種 LLM 供應商，新增一家只要加一個 adapter class，呼叫端不動
  - OpenAI / Gemini / Claude(API) / **Claude 訂閱制** / Ollama（本地離線）
- 最新擴充：**每位使用者可各自串接自己的 Claude 訂閱額度**（OAuth token 逐請求注入、互相隔離）
- 動態模型探測：自動列出各供應商可用模型，不寫死

> 講稿：這個設計讓系統不被單一供應商綁死——可以用付費 API、用個人訂閱、甚至用本地 Ollama 完全離線。最近我還加了「每個使用者帶自己的訂閱」，這樣多人用也各付各的、互不干擾。

*來源：[backend/app/core/llm/adapter.py](../backend/app/core/llm/adapter.py)（`create_adapter` 工廠）。*

## 第 6 頁：技術亮點② — 量化引擎與統計驗證（最硬的數字）

- 三大驗證引擎，由寬到嚴：
  - **Walk Forward**：滾動窗口 OOS 驗證（含 purge / embargo 防時序洩漏）
  - **CPCV（組合淨化交叉驗證）**：所有訓練/測試組合都跑，最嚴格的過擬合檢測
  - **Monte Carlo**：block bootstrap 模擬尾部風險
- 現有策略的統計體質：
  - **CPCV 一致性 100% · Profit Factor 1.45 · Monte Carlo 99.7% · Walk Forward 通過**

> 講稿：這四個數字是整個系統的底氣。PF 1.45 代表策略本身有正期望；CPCV 一致性 100%、Monte Carlo 存活 99.7%，代表它不是過度擬合出來的假象。正因為 alpha 是真的，我才要花這麼大力氣保護它不被亂改。

*來源：CLAUDE.md「系統現有 alpha 是統計強健的（CPCV 一致性 100% / PF 1.45 / MC 99.7% / Walk Forward Alpha pass）」；
[cpcv.py](../backend/app/core/backtest/cpcv.py)、[walk_forward.py](../backend/app/core/backtest/walk_forward.py)、[monte_carlo.py](../backend/app/core/backtest/monte_carlo.py)。*

## 第 7 頁：技術亮點③ — 預測自我驗證閉環

- 從 LLM 回答中**自動抽取結構化預測**（目標價、停損、失效條件）
- 完整生命週期追蹤：`active → hit_target / hit_stop / expired / invalidated`
- 績效統計用**統計金融標準**而非簡單百分比：
  - **Wilson 信賴區間**勝率、**多空方向分層**勝率、**各 Regime 分層**命中率
- 意義：系統會**回頭驗證自己說過的話準不準**，再回饋給 LLM

> 講稿：很多 AI 工具講完就算了。我這套會把每個預測存起來、自動追蹤有沒有命中，還用 Wilson 信賴區間算勝率、分多空、分市場狀態。等於系統會替自己的判斷打分數。

*來源：[backend/app/core/prediction_tracker.py](../backend/app/core/prediction_tracker.py)（`get_winrate_with_ci` 等）。*

## 第 8 頁：技術亮點④ — 工程可靠性設計

- **ML 推論 subprocess 隔離**：主進程永不載入 lightgbm/shap，推論走獨立子進程 → 杜絕 segfault
- **Prompt Caching**：連續分析重用快取，省約 60% token（Anthropic 1h TTL）
- **SSE heartbeat**：streaming 無事件時送心跳，防連線被誤判超時中斷
- **外部訊號 graceful fallback**：衍生品／總經／Fear&Greed 任一 API 失敗仍照常運作

> 講稿：這幾個是「踩過坑才會做的設計」。例如 ML 函式庫在同進程會 segfault，我就把推論丟到獨立子進程；streaming 容易斷線，我加了心跳。這些都是穩定性的細節。

*來源：[backend/app/core/ml_client.py](../backend/app/core/ml_client.py)、[adapter.py](../backend/app/core/llm/adapter.py)。*

> 講稿：先看規模——將近 200 個 commit 是我和 AI 一起完成的，三個月推進 50 個版本。但快不是重點，重點是這麼快還能維持品質，靠的是我建立的一整套護欄。

## 第 10 頁：【主軸】讓 AI 安全協作的「護欄」

- **CLAUDE.md 治理規則**：碰核心檔案前必跑 `/preflight`（shadow mode 收 baseline，劣化 >10% 回滾）
- **Pre-commit 硬限制**（[check_repo_health.py](../backend/scripts/check_repo_health.py)，違反直接 block commit）：
  - `chat.py` ≤ 4500 行 · `chart_state` 賦值 ≤ 33 次 · prompt module ≤ 40 個
- **治理文件三件套**：
  - `SHADOW_FEATURES.md` — 記錄「AI 把 `flag=False` 誤判成 dead code」的真實教訓，制度化驗證流程
  - `CHART_STATE_SCHEMA.md` — 資料結構版本控制，防 prompt 膨脹回歸
- **重構配額**：每 5 個 feature 至少 1 個 refactor，強制償還技術債

> 講稿：這頁是我最想講的。AI 寫得快，但會犯錯——它曾經把一個還在用的功能誤判成廢碼想刪掉。所以我設計了硬性護欄：commit 前自動檢查、超過行數上限直接擋下；還把每次踩的雷寫成文件，變成 AI 下次必讀的規則。等於我用制度把 AI 的能力框在安全範圍內。

## 第 11 頁：【主軸】我在協作中扮演的角色

- 我不是「AI 的打字員」，而是：
  - **架構決策者** — 決定工廠模式、subprocess 隔離、map-reduce 管線等設計
  - **紀律設計者** — 訂出 pre-flight、硬限制、重構配額、commit 規範
  - **統計把關者** — 用 shadow mode 量化「這是真 bug 還是 alpha」，不憑感覺改 code
- 這是 **human-in-the-loop 的正確姿勢**：AI 負責產出，人負責驗證、約束與裁決

> 講稿：總結我的角色——我做的是架構、紀律和統計判斷這些 AI 做不了的決策；AI 負責高速產出。這種分工讓我一個人也能維護一個 7.5 萬行的系統，同時品質不失控。

## 第 12 頁：系統特色／優點

- ✅ **多市場**：加密貨幣 ＋ 台股 2000+ 檔，共用同一套指標引擎
- ✅ **多 LLM 不綁定**：付費 API／個人訂閱／本地離線（Ollama）自由切換
- ✅ **可自我驗證**：預測追蹤閉環 ＋ Wilson 信賴區間勝率
- ✅ **統計嚴謹**：CPCV / Walk Forward / Monte Carlo 三重過擬合防線
- ✅ **工程護欄**：pre-commit 硬限制 ＋ 治理文件 ＋ 自動 drift / health 監控
- ✅ **可離線運作**：搭配 Ollama 可完全本機、不外傳資料

> 講稿：把優點濃縮成一句——它同時做到「功能廣、可驗證、有紀律」，這三件事通常很難兼得。

## 第 13 頁：限制與缺點（誠實面對）

- ⚠️ **技術債**：近期 commit 約 72% 是 bug fix、僅 2% 是重構——修補速度快過償還（CLAUDE.md 已自述）
- ⚠️ **擴展性**：SQLite ＋ 本地檔案，無法水平擴展、不適合高併發
- ⚠️ **無認證／多租戶**：目前是單機工具，多人共用會共享資料
- ⚠️ **單機依賴**：部分功能依賴本機環境（如 Claude CLI 子進程）
- ⚠️ **長任務**：完整分析最長可達 ~14 分鐘，超過部分雲端平台逾時限制

> 講稿：我也很清楚它的不足。技術債是最大問題——所以我才設了重構配額來逼自己還債。擴展性和多租戶是下一步雲端化要解的。我認為能講清楚作品的邊界，本身也是工程成熟度的一部分。

*來源：CLAUDE.md「重構與清理紀律」段落的自我檢討。*
